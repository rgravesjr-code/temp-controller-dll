TEMPSIM 2.2.1 - WINDOWS QUICK START
For Scott: temperature controller and animated test-fixture simulation

1. Save the ZIP locally and use Extract All to extract the entire archive.
   Do not run the application from inside the ZIP.
2. Open the extracted folder and double-click Run TempSim.cmd.
   Alternatively, open the TempSim folder and double-click TempSim.exe.
3. The simulation starts running. Select Run fixture if a previous session
   left it in a controller test scenario.

This package is for 64-bit Windows. It includes the .NET runtime, TempCtl
controller DLL, CanTp DLL, and diagnostic table. No .NET SDK, LabVIEW, CAN
adapter, or connected test hardware is required. Keep the whole TempSim
folder together; do not move only the executable.

WHAT TO TRY

- Choose 10x simulation speed to see warm-up quickly. Available speeds are
  1x, 2x, 3x, 5x, 10x and 20x. Pause freezes temperatures and animation.
- Watch the temperature plot: setpoint, two controller probes, deadbands,
  signal validity limits, UUT inlet and UUT outlet.
- The upper readout shows inlet, outlet, signed delta (outlet minus inlet),
  and actuation heating in watts. During heater warm-up the inlet can be
  hotter. With actuation, the UUT can heat the outlet above the inlet.
- Fixture configuration opens the physics settings. Scroll for motors,
  oil pump, heater, oil volume, fixture thermal mass and fan settings.
  Select Apply physics to apply changes together; closing cancels edits.
- Try 1, 2 or 3 motors. Change load or the fraction of motor power heating
  the fixture to change actuation heat. Change pump flow to see its effect
  on inlet/outlet difference. These are estimated, adjustable values.
- Use the toolbar Stop motors button (or uncheck Motors running) to stop actuation. The motor coasts down and
  temperatures continue responding to stored heat and circulating oil.
- Automatic fan follows the controller cooler relay. To run the fan
  manually, disable Automatic fan and enable Manual fan running.
- The Configuration tab contains setpoint, deadbands, signal limits,
  sensor adjustments, fault injection and logging. Use a decimal point in
  numeric entries; Enter or leaving a field applies controller settings.
- Reset fault clears controller faults; Restart starts a fresh run using
  the configured initial temperature. Run fixture exits scripted scenarios.

The two controller probes both measure the UUT outlet, with separate offsets,
noise and lag. TempCtl expects redundant probes and checks their agreement.
The inlet/outlet display channels are additional modeled temperatures.
The schematic is illustrative: rotations are slowed for visibility.

SAVING SETTINGS AND LOGS

Settings are saved when the application closes, in:
  %LOCALAPPDATA%\TempSim\settings.json
Window placement is saved beside it in window.json.
To start with defaults, close TempSim and rename those files, then reopen it.

Enable Write CSV + .ncl while running in the Configuration tab's Logging
section. Logs appear in %LOCALAPPDATA%\TempSim\logs:
  .csv          controller temperatures, status and diagnostics
  .fixture.csv  inlet/outlet/delta, oil flow and heat channels
  .ncl          CAN frame log for NI-XNET tools (optional)

OPTIONAL COMMAND-LINE RUNS

Open a terminal in the extracted package folder:
  .\TempSim\TempSim.Cli.exe --scenario fixture --seconds 600 --out .\my-run
  .\TempSim\TempSim.Cli.exe --scenario all --out .\controller-checks --quiet

The first runs the fixture and writes temperature/heat/flow logs. The second
runs the 16 controller scenarios with 110 expectations. A zero exit code
means the run passed. CLI runs are unpaced by default; --realtime paces them.

These are simulated, estimated physics, not calibrated test-bench predictions.
The Windows application uses the real TempCtl 3.0.0 controller and CanTp 1.3.1
libraries. The controller itself is unchanged. See SIMULATOR.md for details.

If startup fails, confirm you extracted the whole ZIP and are running the
64-bit Windows package. Share the exact error message with the sender. The
package has been checked locally; machine-specific restrictions may differ.
